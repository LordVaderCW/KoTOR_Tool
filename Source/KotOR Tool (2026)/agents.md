# Automated Contributor Rules

Read [project.md](project.md) and guides for modified directories.

- Confirm `treya/v.1.0.3.4` and inspect status first.
- Preserve unrelated work; never copy Ebonhawk source changes into Treya with documentation.
- Avoid drive-by decompiler cleanup and opaque binary edits.
- Treat designers/resources/project metadata/manifests/command INIs as coupled.
- Test on copied fixtures, never disposable live-game data.
- Treat downloads, build scripts and plugin executables as untrusted.
- Validate both games, unknown fields, UI lifecycle and process paths.
- Use full-framework MSBuild x86 for acceptance and update docs with architecture changes.
