# NWlisten

Source location: `kotor_tool/Tools/3DSMax/NWListen`, visible beneath `Tools > 3DSMax > NWListen` in the KoTOR Tool Visual Studio project. The adjacent `NWMax` folder holds the installed importer snapshot. Builds copy only `NWlisten.ms` and `NWlistenStartup.ms` to the application's `Tools\3DSMax\NWListen` folder. The installer and documentation stay in the source project. Tests remain on disk for standalone validation but are excluded from the Visual Studio project and build output. Use the source `Install.ps1` to update the live listener; building does not install it into Max.

KoTOR Tool's MDL context menu offers **Send to 3DS Max (2021)**. It stages the selected game's MDL/MDX, converts with the installed MDLOps plugin, exports textures and queues an NWmax import. The progress window waits for Max's acknowledgement; success closes automatically, failure remains visible with a close button.

Run `Install.ps1` to install `NWlisten.ms` under `C:\Program Files\Autodesk\3ds Max 2021\scripts\NWlisten`, its startup loader and Light/Dark PNG toolbar icons. Installation only writes these named bridge assets. In an already-running Max session, run `NWlisten.ms` once using Scripting > Run Script. Future launches load it automatically when startup scripts are enabled. Customize User Interface > Toolbars > category **NWlisten** > action **NWlisten** registers the icon-bearing macro for a toolbar. Its NWmax-style floater contains collapsible **Listener**, **Model Import**, and **About NWlisten** rollouts. Listener provides status and Start/Stop controls. Opening the macro preserves the current listening state; closing the floater leaves it unchanged.

The bridge calls the installed NWmax `ImportNWNmdl` with geometry and animations enabled, warnings and importer progress disabled. It adds to the current scene and never resets or saves it. Importer failures can leave partial geometry; inspect Max before retrying. No arbitrary request scripts are executed. MCP is not required.

After import, NWlisten runs the same TCB-to-linear position/rotation/scale conversion as NWmax's **Reset Controllers**, scoped to the newly imported nodes. It then pins the evaluated animation clip endpoints and removes NWmax's generated position/rotation rest-pose keys in the gaps between clips. This prevents a snap to the rest pose while scrubbing between clips; scale keys and frames inside the clips are preserved. Existing scene objects are excluded. The sender's progress window waits until both steps finish before reporting success; a processing error returns an error acknowledgement.

The gap cleanup uses the imported base's animation ranges and Max's `addNewKey` to preserve evaluated endpoint values. Do not copy `rotation.controller.value` directly into rotation-key `.value`: their quaternion conventions differ. No importer parser changes or model-specific frame numbers are used.

Before acknowledging completion, NWlisten also hides newly imported skeleton/proxy meshes whose AuroraTrimesh `render` flag is zero. It uses ordinary scene hiding, retaining nodes, skin references, parenting and animation. Visible meshes that also serve as bones remain visible. Use Max's Unhide controls to reveal the hidden meshes when editing the rig. Existing scene objects are excluded from this automatic step.

For development viewport previews, newly imported mesh names containing `hair` (case insensitive, such as `bthair` and `head_Hair`) receive image-alpha opacity when their Standard material has a Bitmap diffuse map with transparent pixels and no existing opacity map. NWlisten copies the material and maps before changing them, so a shared face/body material stays opaque. The opacity map reads image alpha, keeps the original UV mapping, and the hair material is double sided with hardware viewport display enabled. Missing or opaque textures and existing opacity maps are left alone. This is a preview of the original low-poly cards, not a fur system or a complete emulation of the game's shaders. Other mesh names are not automatically treated as hair.

The settings follow Autodesk's [Bitmaptexture alpha controls](https://help.autodesk.com/cloudhelp/2018/ENU/MAXScript-Help/files/GUID-A3231AD9-2FCB-483B-9F43-3914BD1CE3D6.htm) and [hardware viewport material display](https://help.autodesk.com/cloudhelp/2023/ENU/MAXScript-Help/files/MAXScript-Tools-and-Interaction/Interacting-with-the-3ds-Max/Material-Editor/GUID-BDAD17C6-AC43-4297-8AD3-69F0920ABC59.html). Diffuse color and opacity use separate bitmap-map instances; alpha must not be enabled indiscriminately on all model materials.

## Protocol and lifecycle

`<KoTOR Tool executable directory>\working\NWlisten\jobs\<GUID>` holds fixed asset filenames, including model and texture exports. The sender atomically publishes `request.ready` containing `NWlisten/1`. A Max UI-thread timer claims it by renaming to `request.working`, rejects requests older than two minutes, then atomically publishes `result.txt`: `OK` or `ERROR`, newline, detail. Claimed requests are never replayed. Requests withdrawn before claim are not imported. Once claimed, an import cannot be cancelled by closing KoTOR Tool's window; Max may finish later. The sender waits up to ten minutes for a result.

Before connecting, the sender creates this application-local folder and registers `Application.StartupPath` in the 64-bit registry view at `HKCU\Software\KotOR Tool\NWlisten`, string value `ApplicationDirectory`. This stores only a discovery pointer; queue files and the heartbeat are all beside the application. Max reads the pointer on each poll, so an already-open listener follows the next sending application's location. Before the first send it waits for registration. An unwritable application folder reports failure in the progress window; there is no user-profile AppData fallback. When moving between application folders, the listener removes its own previous heartbeat but retains exported assets.

The listener updates `listener.alive`; KoTOR Tool checks freshness before preparing work. If Max is closed, it launches Max 2021 with the bridge script. If Max is already open without NWlisten, the progress window explains how to start it. Use one listening Max instance per user: with multiple listeners the first claimant receives the job.

Assets remain in the job folder because Max references exported textures. KoTOR Tool no longer offers working-directory cleanup or cleaning before model export. Do not remove successful job folders until their scene assets have been relocated. Old exports in user-profile AppData and the earlier application-local `AppData\NWlisten` location are deliberately retained for saved scenes; new transfers use `working\NWlisten`. No live game files are modified. The sender uses ProgramW6432 to locate the 64-bit Max installation.

## Validation

Build the solution with full-framework MSBuild, Debug/x86. `tests/BridgeSmoke.ms` runs only in an isolated `3dsmaxbatch.exe` process, uses copied geometry/TSL fixtures, preserves a sentinel scene object, checks single consumption and missing-model errors. Tests write their own uniquely named queue beneath `tests`. Never run these batch tests in an open working scene.

Run `tests/TestApplicationStorage.ps1` with `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File` after building. It invokes the compiled x86 sender's registration helper against a temporary fixture directory, checks storage failure without fallback, and runs the bridge tests in 64-bit Max batch. It restores the previous registry pointer in `finally`. The batch suite also verifies paths with spaces, absent registration, relocation, heartbeat cleanup and retained assets.
